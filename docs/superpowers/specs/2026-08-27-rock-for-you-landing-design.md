# Rock For You Landing Page — Design Spec

**Date:** 2026-08-27
**Status:** Approved by user, ready for implementation planning

## Goal

Add the "Rock For You" landing page (a loja de camisetas de banda/anime/cultura pop) to the
portfolio's `/landing-pages` section, following the same static self-contained pattern used by
Bellos and ImperioFit. While converting it, apply a custom three.js + GLSL shader texture to the
hero background and the two orange/cream decorative sections ("Frase do dia" and "Bandas"), with
a mouse-hover interaction combining a focus lens and a ripple distortion.

## Non-goals

- No changes to the Bellos or ImperioFit landing pages.
- No changes to `ds-bundle/`, `.ds-sync/`, `.design-sync/` (unrelated design-system sync tooling,
  confirmed during exploration to have nothing to do with this landing page).
- The original `Rock For You v2.dc.html` and `support.js` (Claude Design canvas artboard source)
  are left in place, untouched, just no longer referenced by any route.
- No WhatsApp phone number configurability — it's hardcoded (the `.dc.html` had it as an editable
  "prop" for the Design Canvas editor UI, which no longer applies).

## 3. Static content conversion (HTML/CSS/vanilla JS)

All `{{ }}` template bindings, `sc-for` loops, `style-hover` attributes, and the `DCLogic`
component class from the `.dc.html` source are converted to plain HTML + a single `<style>` block
in `<head>` + a single `<script>` block before `</body>`, matching Bellos/ImperioFit's structure.
`style-hover="..."` attributes become regular CSS classes with a `:hover` rule (e.g.
`.rfy-nav-link:hover { color: #EFE9E0; }`).

**Static sections (hardcoded HTML, no JS needed):** header/nav, scrolling category marquee,
"O que você encontra na loja" grid (8 items — `goods` array in source, hardcode as 8 `<div>`s),
"Bandas" list (12 band/anime names), photo gallery (6 images), FAQ (4 Q&A pairs), "A loja"
section (address + Google Maps iframe embed, same `src` URL as source), footer.

**Dynamic behavior (vanilla JS, replacing the React `Component` class):**

- **Quote shuffle** — the `QUOTES` array (8 entries) is copied verbatim into a `const QUOTES = [...]`
  in the page's script. On load, pick `Math.floor(Math.random() * QUOTES.length)` and render into
  `#rfy-quote` / `#rfy-quote-author`. The "Outra frase" button's click handler:
  ```js
  let quoteIndex = /* initial random index */;
  document.getElementById('rfy-shuffle-btn').addEventListener('click', () => {
    quoteIndex = (quoteIndex + 1 + Math.floor(Math.random() * (QUOTES.length - 1))) % QUOTES.length;
    renderQuote(quoteIndex);
  });
  function renderQuote(i) {
    const el = document.getElementById('rfy-quote-block');
    el.classList.remove('is-in'); // restart the fade-in transition
    void el.offsetWidth; // force reflow so the class removal takes effect before re-adding
    document.getElementById('rfy-quote').textContent = `"${QUOTES[i].t}"`;
    document.getElementById('rfy-quote-author').textContent = QUOTES[i].a;
    requestAnimationFrame(() => el.classList.add('is-in'));
  }
  ```
  `.rfy-quote-block { opacity: 0; transform: translateY(10px); transition: opacity .45s ease, transform .45s ease; } .rfy-quote-block.is-in { opacity: 1; transform: translateY(0); }` replaces the GSAP `animateQuote` stagger.

- **Catalog filter + carousel** — the `CATALOG` object (3 arrays: `pop`, `rock`, `anime`, 7-8 items
  each, copied verbatim from source) drives a `renderCatalog(category)` function that rebuilds the
  card track's `innerHTML` from the array (each card: image + tag badge + name + note + a
  "Consultar →" link pointing to `waLink(`Oi! Vi "${item.name}" no site da Rock For You e quero
  saber mais.`)`). The 3 category buttons toggle an `.is-active` class (CSS: active = orange bg +
  dark text, inactive = transparent bg + cream text — same as source's `bg()`/`fg()` helpers) and
  call `renderCatalog(cat)`, which also does `track.scrollTo({ left: 0, behavior: 'smooth' })` and
  a short CSS fade-in on the newly inserted cards (`opacity`/`translateY` transition per card,
  staggered via a small per-card `transition-delay`, replacing the GSAP `animateCards` stagger).
  The `←`/`→` buttons call `track.scrollBy({ left: dir * track.clientWidth * 0.8, behavior:
  'smooth' })`, identical to source.

- **WhatsApp links** — a single helper replaces the source's `wa()` method:
  ```js
  const WA_NUMBER = '5521994208796'; // 55 (Brazil) + 21994208796, matching source's wa() logic
  function waLink(text) {
    return `https://wa.me/${WA_NUMBER}?text=${encodeURIComponent(text)}`;
  }
  ```
  Used for: header/hero/footer "WhatsApp" CTAs (`waLink('Oi! Vi o site da Rock For You e quero
  saber o que tem na loja.')`), "Bandas" section CTA (`waLink('Oi! Estou procurando uma peça
  específica: ')`), and each catalog card's "Consultar →" link (built per-item in
  `renderCatalog`).

- **Maps link** — a plain constant, computed once at parse time (no need to recompute per
  render):
  ```js
  const MAPS_LINK = 'https://www.google.com/maps/dir/?api=1&destination=' +
    encodeURIComponent('Avenida Governador Leonel de Moura Brizola, 1741, Duque de Caxias, RJ');
  ```

- **Scroll reveals** — replaces GSAP + ScrollTrigger with one shared `IntersectionObserver`:
  ```js
  const revealObserver = new IntersectionObserver((entries) => {
    entries.forEach((entry) => {
      if (entry.isIntersecting) {
        entry.target.classList.add('is-visible');
        revealObserver.unobserve(entry.target);
      }
    });
  }, { threshold: 0, rootMargin: '0px 0px -12% 0px' });
  document.querySelectorAll('[data-reveal]').forEach((el) => revealObserver.observe(el));
  ```
  CSS: `[data-reveal] { opacity: 0; transform: translateY(24px); transition: opacity .7s
  cubic-bezier(.16,1,.3,1), transform .7s cubic-bezier(.16,1,.3,1); } [data-reveal].is-visible {
  opacity: 1; transform: translateY(0); }`. Hero elements (`data-hero` in source) fade/slide in
  immediately on page load instead (staggered `transition-delay` per element), since they're
  above the fold and don't need scroll-triggering.

- **Hero parallax** — replaces the GSAP `scrollTrigger: { scrub: true }` on the hero background
  image with a plain scroll listener:
  ```js
  let ticking = false;
  window.addEventListener('scroll', () => {
    if (ticking) return;
    ticking = true;
    requestAnimationFrame(() => {
      const heroSection = document.getElementById('top');
      const rect = heroSection.getBoundingClientRect();
      const progress = Math.min(Math.max(-rect.top / rect.height, 0), 1);
      document.getElementById('rfy-hero-bg').style.transform =
        `translateY(${progress * 12}%)`;
      ticking = false;
    });
  });
  ```

- **Reduced motion** — wrap the reveal-on-load stagger, the `IntersectionObserver` transitions,
  and the hero parallax listener registration in a single check:
  ```js
  const prefersReducedMotion = window.matchMedia('(prefers-reduced-motion: reduce)').matches;
  ```
  When true: skip attaching the scroll listener (parallax), and apply `.is-visible` to every
  `[data-reveal]` element immediately instead of observing (content just appears, no motion).

## 4. Three.js / GLSL shader texture

### 4.1 Where it applies

Three independent instances, each behind its section's content (`z-index` below text,
`pointer-events: none` on the `<canvas>` — the hover target is the section element, not the
canvas):

| Instance | Container | Data source | Shape |
|---|---|---|---|
| `hero` | `#top` (hero section) | Hero photo texture (`uploads/Gemini_Generated_Image_u1wpswu1wpswu1wp.png`) | Full rectangle (section bounds) |
| `frase` | "Frase do dia" section | Procedural noise | Same jagged `clip-path` polygons already in source (two layers: `#F7D9CF` outline behind, `#EA3B21` main shape in front — reproduced as two stacked canvases or two clip-path divs each containing their own canvas; simplest: **one canvas per color layer**, i.e. 2 canvases for this section) |
| `bandas` | "Bandas" section | Procedural noise | Same jagged `clip-path` polygons already in source (2 canvases, same reasoning) |

So there are 4 canvases total (1 hero + 2 for "Frase" + 2 for "Bandas" — one per clip-path layer),
each driven by its own `ShaderPanel` instance, but all stepped by one shared `requestAnimationFrame`
loop (see 4.5).

### 4.2 Setup

Three.js loaded via CDN: `<script src="https://cdn.jsdelivr.net/npm/three@0.160.0/build/three.min.js"></script>`
in `<head>`, alongside the existing Google Fonts `<link>` tags (no other external dependency is
added — GSAP is dropped per section 3).

`ShaderPanel` (a small class defined inline in the page's `<script>`, not a separate file — this
page is meant to stay a single self-contained HTML file like Bellos/ImperioFit):

```js
class ShaderPanel {
  constructor({ canvas, mode, texture, colorA, colorB, colorC }) {
    this.canvas = canvas;
    this.mode = mode; // 'photo' | 'procedural'
    this.renderer = new THREE.WebGLRenderer({ canvas, alpha: true, antialias: false });
    this.renderer.setPixelRatio(Math.min(window.devicePixelRatio || 1, 1.5));
    this.scene = new THREE.Scene();
    this.camera = new THREE.OrthographicCamera(-1, 1, 1, -1, 0, 1);
    this.uniforms = {
      uTime: { value: 0 },
      uResolution: { value: new THREE.Vector2(1, 1) },
      uMouse: { value: new THREE.Vector2(0.5, 0.5) },
      uHover: { value: 0 },
      uRippleTime: { value: -1000 },
      uRippleOrigin: { value: new THREE.Vector2(0.5, 0.5) },
      uMode: { value: mode === 'photo' ? 1 : 0 },
      uTexture: { value: texture || null },
      uColorA: { value: new THREE.Color(colorA) }, // dark ink
      uColorB: { value: new THREE.Color(colorB) }, // light (cream or pink)
      uColorC: { value: new THREE.Color(colorC) }, // accent (orange)
      uReducedMotion: { value: prefersReducedMotion ? 1 : 0 },
    };
    const material = new THREE.ShaderMaterial({
      uniforms: this.uniforms,
      vertexShader: SHADER_VERTEX,
      fragmentShader: SHADER_FRAGMENT,
      transparent: true,
    });
    const geometry = new THREE.PlaneGeometry(2, 2);
    this.scene.add(new THREE.Mesh(geometry, material));
    this.visible = false;
    this.resize();
  }

  resize() {
    const rect = this.canvas.parentElement.getBoundingClientRect();
    const dpr = this.renderer.getPixelRatio();
    this.canvas.width = rect.width * dpr;
    this.canvas.height = rect.height * dpr;
    this.canvas.style.width = rect.width + 'px';
    this.canvas.style.height = rect.height + 'px';
    this.renderer.setSize(rect.width, rect.height, false);
    this.uniforms.uResolution.value.set(rect.width, rect.height);
  }

  setMouse(nx, ny) { this.uniforms.uMouse.value.set(nx, ny); }

  ping(nx, ny, timeNow) {
    this.uniforms.uRippleOrigin.value.set(nx, ny);
    this.uniforms.uRippleTime.value = timeNow;
  }

  render(timeNow) {
    if (!this.visible) return;
    this.uniforms.uTime.value = timeNow;
    this.renderer.render(this.scene, this.camera);
  }
}
```

`uMode` lets one fragment shader source serve both the hero (photo luminance) and the two
procedural sections (noise luminance) — see 4.4.

### 4.3 Fragment shader — vertex shader

Trivial pass-through (full-screen quad, `PlaneGeometry(2,2)` with an `OrthographicCamera(-1,1,1,-1)`
already spans clip space, so no projection matrix math is needed beyond passing `uv`):

```glsl
varying vec2 vUv;
void main() {
  vUv = uv;
  gl_Position = vec4(position.xy, 0.0, 1.0);
}
```

### 4.4 Fragment shader — full pipeline

```glsl
precision highp float;
varying vec2 vUv;

uniform float uTime;
uniform vec2 uResolution;
uniform vec2 uMouse;
uniform float uHover;
uniform float uRippleTime;
uniform vec2 uRippleOrigin;
uniform float uMode; // 0 = procedural noise, 1 = photo texture
uniform sampler2D uTexture;
uniform vec3 uColorA; // dark ink
uniform vec3 uColorB; // light (cream/pink)
uniform vec3 uColorC; // accent (orange)
uniform float uReducedMotion;

// -- hash/value noise (procedural mode) --
float hash(vec2 p) {
  p = fract(p * vec2(123.34, 456.21));
  p += dot(p, p + 45.32);
  return fract(p.x * p.y);
}
float noise(vec2 p) {
  vec2 i = floor(p), f = fract(p);
  float a = hash(i), b = hash(i + vec2(1.0, 0.0));
  float c = hash(i + vec2(0.0, 1.0)), d = hash(i + vec2(1.0, 1.0));
  vec2 u = f * f * (3.0 - 2.0 * f);
  return mix(a, b, u.x) + (c - a) * u.y * (1.0 - u.x) + (d - b) * u.x * u.y;
}
float fbm(vec2 p) {
  float v = 0.0, amp = 0.55;
  for (int i = 0; i < 3; i++) {
    v += amp * noise(p);
    p *= 2.0;
    amp *= 0.5;
  }
  return v;
}

// 4x4 Bayer ordered-dither matrix, normalized 0..1
float bayerDither(vec2 fragCoord) {
  int x = int(mod(fragCoord.x, 4.0));
  int y = int(mod(fragCoord.y, 4.0));
  float m[16];
  m[0]=0.0; m[1]=8.0; m[2]=2.0; m[3]=10.0;
  m[4]=12.0; m[5]=4.0; m[6]=14.0; m[7]=6.0;
  m[8]=3.0; m[9]=11.0; m[10]=1.0; m[11]=9.0;
  m[12]=15.0; m[13]=7.0; m[14]=13.0; m[15]=5.0;
  return m[y * 4 + x] / 16.0;
}

void main() {
  vec2 uv = vUv;
  vec2 aspect = vec2(uResolution.x / uResolution.y, 1.0);

  // -- distance to mouse (lens) --
  float distToMouse = distance(uv * aspect, uMouse * aspect);
  float lens = uHover * smoothstep(0.35, 0.0, distToMouse); // 1 near cursor, 0 far away

  // -- ripple (decays with distance and with time since the last ping) --
  float dt = uTime - uRippleTime;
  float rippleEnvelope = uReducedMotion > 0.5 ? 0.0 : exp(-dt * 1.6) * step(0.0, dt);
  float distToRipple = distance(uv * aspect, uRippleOrigin * aspect);
  float ripple = sin(distToRipple * 40.0 - dt * 6.0) * rippleEnvelope
                 * smoothstep(0.6, 0.0, distToRipple);

  // -- pixelation grid: coarser far from cursor, finer near it --
  float baseGrid = mix(28.0, 64.0, lens); // cells across the shorter axis
  vec2 grid = vec2(baseGrid * aspect.x, baseGrid);
  vec2 rippledUv = uv + normalize(uv - uRippleOrigin + 1e-5) * ripple * 0.01;
  vec2 cell = floor(rippledUv * grid);
  vec2 cellUv = fract(rippledUv * grid);
  vec2 cellCenterUv = (cell + 0.5) / grid;

  // -- luminance sample: photo (mode 1) or fbm noise (mode 0) --
  float lum;
  if (uMode > 0.5) {
    lum = dot(texture2D(uTexture, cellCenterUv).rgb, vec3(0.299, 0.587, 0.114));
  } else {
    lum = fbm(cellCenterUv * 6.0 + uTime * 0.02 * (1.0 - uReducedMotion));
  }

  // -- contrast boost --
  float contrast = 1.35;
  lum = clamp((lum - 0.5) * contrast + 0.5, 0.0, 1.0);
  lum = clamp(lum + ripple * 0.15, 0.0, 1.0); // ripple nudges local brightness too

  // -- halftone dot: radius grows with luminance, shrinks/sharpens near cursor --
  float dotRadius = mix(lum * 0.42, lum * 0.48 + 0.04, lens);
  float dist = distance(cellUv, vec2(0.5));
  float dot = smoothstep(dotRadius + 0.04, dotRadius, dist);

  // -- ordered dithering: quantize `dot` against the Bayer threshold --
  float threshold = bayerDither(gl_FragCoord.xy);
  float dithered = step(threshold, dot);

  // -- palette: dark base, light dot, orange accent on the brightest/nearest-cursor dots --
  vec3 color = mix(uColorA, uColorB, dithered);
  float accentMix = dithered * smoothstep(0.72, 1.0, lum) * mix(0.15, 0.6, lens);
  color = mix(color, uColorC, accentMix);

  gl_FragColor = vec4(color, 1.0);
}
```

Notes for the implementer:
- `uMode` is set once per instance at construction (`1` for hero, `0` for the two procedural
  instances) and never changes at runtime.
- For the two procedural instances (`frase`, `bandas`), `uColorA`/`uColorB`/`uColorC` are set per
  canvas to match that layer's original flat color pair (e.g. the `#F7D9CF` layer uses
  `uColorA = #0C0B0B, uColorB = #F7D9CF, uColorC = #EA3B21`; the `#EA3B21` layer uses
  `uColorA = #0C0B0B, uColorB = #EA3B21, uColorC = #F7D9CF` — swapping which color is the dot vs.
  accent between the two stacked layers keeps the original two-tone contrast between them).
- For the hero, `uColorA = #0C0B0B, uColorB = #EFE9E0, uColorC = #EA3B21`.
- The existing dark gradient overlay (`linear-gradient(to right, rgba(12,11,11,0.94) 0%, ...)`) on
  top of the hero stays as a plain CSS layer above the canvas, for text legibility — unchanged
  from source.

### 4.5 Interaction wiring (shared loop, one per page)

```js
const panels = []; // populated as each ShaderPanel is constructed
let lastMoveTime = -1000;

function bindHover(sectionEl, panelsForSection) {
  sectionEl.addEventListener('pointermove', (e) => {
    const rect = sectionEl.getBoundingClientRect();
    const nx = (e.clientX - rect.left) / rect.width;
    const ny = 1.0 - (e.clientY - rect.top) / rect.height; // flip Y for GL space
    panelsForSection.forEach((p) => p.setMouse(nx, ny));
    lastMoveTime = performance.now() / 1000;
  });
  sectionEl.addEventListener('pointerleave', () => {
    lastMoveTime = -1000; // lens fades out (see hoverTarget below)
  });
  sectionEl.addEventListener('touchstart', (e) => {
    const rect = sectionEl.getBoundingClientRect();
    const t = e.touches[0];
    const nx = (t.clientX - rect.left) / rect.width;
    const ny = 1.0 - (t.clientY - rect.top) / rect.height;
    const now = performance.now() / 1000;
    panelsForSection.forEach((p) => { p.setMouse(nx, ny); p.ping(nx, ny, now); });
  }, { passive: true });
}

function tick() {
  const now = performance.now() / 1000;
  const hoverTarget = (now - lastMoveTime < 0.15 && !prefersReducedMotion) ? 1 : 0;
  panels.forEach((p) => {
    p.uniforms.uHover.value += (hoverTarget - p.uniforms.uHover.value) * 0.12; // eased
    p.render(now);
  });
  requestAnimationFrame(tick);
}
requestAnimationFrame(tick);
```

A ripple `ping()` is also triggered from `pointermove` when the cursor's movement speed crosses a
small threshold (comparing consecutive positions), not on every move event, so the ripple reads as
a deliberate wave rather than firing continuously.

### 4.6 Visibility gating (performance)

```js
const visibilityObserver = new IntersectionObserver((entries) => {
  entries.forEach((entry) => {
    const panelsForSection = sectionPanelMap.get(entry.target);
    panelsForSection.forEach((p) => { p.visible = entry.isIntersecting; });
  });
}, { threshold: 0 });
[heroSection, fraseSection, bandasSection].forEach((el) => visibilityObserver.observe(el));
```

`ShaderPanel.render()` early-returns when `visible` is false (see 4.2), so
`renderer.render()` is simply never called for off-screen sections — the shared `tick()` loop
keeps running (cheap) but skips the expensive part.

### 4.7 Fallback (no WebGL / CDN failure)

The canvases are created and `ShaderPanel` instances constructed inside a single `try/catch` at
page-load time:

```js
try {
  if (!window.THREE) throw new Error('three.js failed to load');
  initShaderPanels();
} catch (err) {
  console.warn('Rock For You: shader textures disabled —', err.message);
  // Do nothing else: the canvases are simply never inserted/rendered, and the
  // sections keep their original CSS-only backgrounds (hero photo with the
  // grayscale/contrast/brightness filter; "Frase"/"Bandas" with their flat
  // clip-path color layers), because those CSS rules are unconditional and
  // not dependent on JS running.
}
```

This means the base CSS for all three sections must be written as if the shader will never load
(fully functional/attractive on its own), with the canvases layered on top only when JS
successfully initializes them.

## 6. Testing / verification approach

No unit-test framework applies here (this is a static HTML asset outside the Next.js
component tree). Verification is manual + build-level:

1. `pnpm build` / `pnpm lint` must still pass (the only TypeScript/React changes are the new
   `page.tsx` redirect and the `landing-pages.ts` array entry).
2. Run the dev server and manually check, in the browser, at each step of implementation:
   - `/landing-pages` shows the new Rock For You card (thumbnail, logo overlay, description) and
     links to `/landing-pages/rock`.
   - `/landing-pages/rock` redirects to `/landing-pages/rock/index.html` and the full page renders
     with no console errors.
   - Quote shuffle button cycles quotes; category filter buttons switch catalog content and
     restart the horizontal scroll; prev/next arrows scroll the track; all WhatsApp/Maps links
